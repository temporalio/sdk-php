## Rules

### No essay docblocks
**Source**: CLAUDE.md "Comments" section + recent remediation cycle (8 docblocks deleted as essays)
**Rule**: When generating PHP code, do NOT write docblocks for trivial methods. Method names plus parameter and return types already explain WHAT the code does. A docblock is allowed ONLY when it captures something a reader cannot recover from the code itself: a hidden constraint, a non-obvious invariant, a workaround tied to a specific bug, or behaviour that would surprise a reader. Keep docblocks to one short line whenever possible. NEVER write multi-paragraph essays. NEVER restate what the code does. NEVER reference the current task or PR. If removing the docblock would not confuse a future reader, do not write it.

### No informal abbreviations in identifiers
**Source**: CLAUDE.md "Naming" + .ai-factory/rules/base.md + remediation rename (`$sce` → `$exception`)
**Rule**: Use full words for variables, parameters, properties, and method names. Forbidden examples: `$ctx`, `$opts`, `$ref`, `$attrs`, `$impl`, `$sce`, `$opt`. Standard short-name exceptions: `$e` for an exception in a `catch`, `$i` / `$j` for loop counters in narrow scope. Established protocol abbreviations baked into wire-level contracts (RPC, URL, URI, ID) are allowed. When in doubt, write the full word.

### Full-message exception assertions
**Source**: CLAUDE.md "Exception tests"
**Rule**: When asserting exception messages, use `$this->expectExceptionMessage('exact full text')`. Do NOT use `$this->expectExceptionMessageMatches('/regex fragment/')`. Full-message assertions catch accidental message changes and are easier to read. Only when the message contains genuinely dynamic parts (timestamps, UUIDs, generated IDs) is `assertStringContainsString` on the caught exception acceptable. For static messages, always assert the full string.

### Tests must exercise real behaviour
**Source**: CLAUDE.md "Tests must exercise real behaviour"
**Rule**: Every new test must be capable of failing on a real production change. Do not write tautologies — tests where the only thing happening is reading back a value just written:
- WRONG: `$value = 5; self::assertSame(5, $value);`
- WRONG: `$dto = new Foo(name: 'x'); self::assertSame('x', $dto->name);`
For each new test, ask: "what production change would make this fail?" If the answer is "none", do NOT write the test. Replace it with something that exercises a method call, a state transition, a serializer round-trip, or an error path.

### `if`-statements over short-circuit side effects
**Source**: CLAUDE.md "Control flow"
**Rule**: Do not smuggle imperative actions into boolean expressions. Each statement should either make a decision (a condition guarding a block) OR perform an action — never both. WRONG: `$result === 'ok' && $handler->continue();`, `$value !== null or throw new \LogicException('missing value');`. RIGHT: explicit `if ($result === 'ok') { $handler->continue(); }` and `if ($value === null) { throw new \LogicException('missing value'); }`.

**Source**: Fiber-mode stabilization — `MutexRunLockedTest::runLockedAndCancel` regression — cancel-driven `setFiberMode(false)` flipped the flag on a child scope whose Fiber was still suspended on `Mutex::lock()`; when the lock later resolved, the bridge resumed the Fiber and the next `FiberHelper::await` threw `OutOfContextException` because `fiberMode` was already false

### Fiber-mode-conditional context save/restore in `Scope::startScope()`
**Source**: Fiber-mode stabilization — root cause of `MutexRunLockedTest::runLockedAndCancel` AND `Harness/ChildWorkflow/CancelAbandon::childWorkflowInClosingInnerScope`
**Rule**: `Scope::startScope()` must save+restore `Facade::getCurrentContext()` around `$scope->start(...)` ONLY when the parent scope is in Fiber mode:
```php
public function startScope(callable $handler, bool $detached, ?string $layer = null): CancellationScopeInterface
{
    $fiberMode = $this->scopeContext->isFiberMode();
    $savedContext = $fiberMode ? Facade::getCurrentContext() : null;
    $scope = $this->createScope($detached, $layer);
    $scope->start($handler(...), EncodedValues::empty(), false);
    if ($fiberMode) {
        Facade::setCurrentContext($savedContext);
    }
    return $scope;
}
```
**Why:** In Fiber mode, `Workflow::async()` / `Workflow::runLocked()` synchronously create+drive a child scope; the child's `Scope::next()` calls `makeCurrent()` which overwrites the static `Facade::$ctx` with the CHILD scope's context. The parent Fiber body has no yield/suspend between the call and its next statement, so the next `Workflow::await(...)` reads the wrong context — the await registers on the child scope instead of the parent and the workflow hangs.
**In Generator mode**, the parent Generator yields between `Workflow::async()` and the next call, and the loop re-makes-current via `nextPromise.$onFulfilled` → `defer` → tick. Unconditional restore in `startScope()` breaks this Generator handoff. Hence the Fiber-mode gate.

```php

```

### `Workflow::async()` returns `FiberScope` — use `->join()` to wait for scope completion
**Source**: Fibers test-replication — `CancelTryCancelTest` mechanical yield-removal converted `yield $scope` to `$scope;` (no-op statement); cancel queued but the fiber didn't wait for it. **Rule**: In Fibers mode, `Workflow::async(...)` and `Workflow::asyncDetached(...)` return `Temporal\Experiments\Fibers\FiberScope` (which `implements CancellationScopeInterface`). When the original Generator workflow used `yield $scope` (typically after `$scope->cancel()`) to await scope settlement, the Fibers replica MUST use `$scope->join()` instead of leaving `$scope;` (which is a no-op after mechanical yield-removal). ```php

```php
yield $scope;

// Fibers:
$scope->cancel();
$scope->join();
```
Without the explicit join, the cancel command queues but the fiber returns immediately, and downstream `Workflow::await*` may race the cancellation propagation. `$scope->join()` throws `CanceledFailure` for cancelled scopes — wrap in `try/catch` if needed (mirroring the original's `catch (CanceledFailure)` after `yield $scope`).

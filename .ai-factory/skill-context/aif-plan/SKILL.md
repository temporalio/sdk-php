## Rules

### Fiber/Generator coexistence — treat as parallel public API surfaces
**Source**: The fibers branch exposes `\Temporal\Experiments\Fibers\Workflow` as a drop-in alternative to `\Temporal\Workflow` for users who prefer Fiber-based workflow bodies without `yield`. Both must keep working simultaneously.
**Rule**: When planning ANY change in `src/Workflow/`, `src/Internal/Workflow/`, `src/Interceptor/`, or `src/Internal/Support/StackRenderer.php`, plan tasks must explicitly state how the change affects each path:
- **Generator mode** (`use \Temporal\Workflow` + `yield`) — the legacy primary path, baseline tests in `tests/Acceptance/Extra/*` (non-Fibers subdirs)
- **Fiber mode** (`use \Temporal\Experiments\Fibers\Workflow`, no `yield`) — experimental, baseline tests in `tests/Acceptance/Extra/.../Fibers/`
The `Scope::createFiberHandler` bridge wraps every workflow handler in a Fiber regardless of caller mode. A "Generator-only" assumption is wrong: every handler runs inside a Fiber whose body just returns the user's Generator object when the user wrote `yield`. Plan tasks must verify both code paths.

Add it to the plan; do not assume reviewers will catch it.

### Fiber-mirror test plans MUST enumerate mechanical-conversion edge cases
**Source**: Fibers test-replication — mechanical yield-removal alone was insufficient. 5 distinct extra-rewrite patterns surfaced across 46 mirrored tests (activity name mismatch, `Workflow\X` expression alias, `Promise::race` blocking calls, global `\define` collision, plugin name collision).
**Rule**: When planning a Fiber-mirror of an existing acceptance test, EXTEND the existing 3-task template (rename, TaskQueueResolver entry, phpunit.xml.dist categorization) with up to 5 additional tasks per mirrored test — include each ONLY when its trigger pattern appears in the original:

4. **Activity call-site / prefix alignment** (trigger: original has `Workflow::executeActivity('<bare-name>', ...)` AND the trans-script will inject `prefix: 'Fibers_'` into the `#[ActivityInterface]`): rewrite each bare-string call site to `Workflow::executeActivity('Fibers_<bare-name>', ...)`. Otherwise `RETRY_STATE_TIMEOUT` because wire name = `<prefix><method>` mismatches the workflow's request.

5. **`Workflow\X` expression-position FQN** (trigger: original references `Workflow\ChildWorkflowOptions`, `Workflow\ParentClosePolicy`, `Workflow\CancellationScopeInterface`, etc., outside `use` statements): rewrite each to `\Temporal\Workflow\<Class>`. The Fibers facade alias shadows the attribute namespace at runtime → fatal `Class not found`.

6. **`Promise::race/all/any/some` + blocking calls** (trigger: original has `yield Promise::race(...)` whose array contains `Workflow::timer(N)`, `Workflow::await(...)`, `$stub->getResult()`, `$stub->start()`, etc.): rewrite blocking calls to their `*Promise()` / `*Async()` variants and wrap the combinator in `FiberHelper::await(...)`. Add `use Temporal\Experiments\Fibers\FiberHelper;` import. Each blocking call would otherwise sequentially suspend the fiber, defeating the parallel-promise semantic.

7. **Global `\define()` namespacing** (trigger: original has top-level `\define('CONST_NAME', value)`): rewrite to `\define(__NAMESPACE__ . '\\CONST_NAME', value)`. Same-file references stay unchanged (PHP namespace fallback). Avoids `Constant X already defined` warnings when both original and replica load.

8. **Plugin `getName()` uniqueness** (trigger: original test declares plugin classes implementing `ClientPluginInterface`/`ConnectionPluginInterface`/`WorkerPluginInterface`): append `-fibers` suffix to every `getName()` return value AND update any `expectExceptionMessage('Duplicate plugin "<name>"')` assertions. Plugin registry is process-global.

### `Workflow::async()->cancel()` plans need explicit `->join()` task
**Source**: Fibers test-replication — `CancelTryCancelTest` mechanical yield-removal converted `yield $scope` to bare `$scope;` (no-op); cancel queued but the fiber never waited for it. Fixed by introducing `FiberScope::join()` and updating the test to call it.
**Rule**: When the Fiber-mirror plan covers a workflow that uses `Workflow::async(...)` or `Workflow::asyncDetached(...)` and the original generator-mode body has `yield $scope` (typically after `$scope->cancel()`), the plan MUST include a task: "after mechanical yield-removal, the bare `$scope;` is a no-op — replace with `$scope->join()`". `Workflow::async()` in the Fibers facade returns `FiberScope` (a wrapper over `CancellationScopeInterface` exposing `join(): mixed` which does `FiberHelper::await($inner)`). Without explicit join, the cancel command queues but the fiber returns immediately; downstream `Workflow::await*` may race the cancellation propagation. Pattern: `$scope->cancel(); $scope->join();` — wrap in `try/catch (CanceledFailure)` if needed (mirroring the original's `catch (CanceledFailure)` after `yield $scope`).

### Typed child workflow stub plans must address auto-await deadlock
**Source**: Fibers test-replication — `Harness/ChildWorkflow/Fibers/SignalTest`, `Harness/Signal/Fibers/ChildWorkflowTest` are unfixable via pure mechanical yield-removal. The original Generator pattern `$handle = $wf->run(); yield $wf->signal(...); return yield $handle;` relies on `$wf->run()` returning an unawaited promise. After yield-removal in Fibers, `FiberProxy::__call` auto-awaits `$wf->run()` until child completes — but child blocks on signal that isn't sent yet. Deadlock until parent's StartToClose timeout fires.
**Rule**: When planning a Fiber-mirror of a test whose original workflow body uses `Workflow::newChildWorkflowStub(C::class)` AND relies on the unawaited-promise pattern (any `$wf->run()` not immediately wrapped in `yield`, followed by `yield $wf->signal(...)` or other ordering), the plan MUST include a task: "rewrite the workflow to use `Workflow::newUntypedChildWorkflowStub('<wire-type>', $options)` with explicit `startAsync()` / `signalAsync()` / `getResultAsync()` calls, then `FiberHelper::await(...)` each promise in the required order". `FiberProxy::__call` always awaits; there is no opt-out. The mechanical yield-removal alone produces a deadlock — note this in the plan as a deviation from the "minimal diff" principle.
